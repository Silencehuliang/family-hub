## 1. 设计目标与原则

| 目标 | 说明 |
|------|------|
| 可组合扩展 | 模块化架构，新功能只改注册中心一处 |
| 移动优先 PWA | 安装即用、离线可用、推送可达 |
| 边缘 + 无服务器 | 全栈托管在 Cloudflare，零运维 |
| 安全可信 | 设备+PIN 双因子，敏感配置加密 |
| 自动化交付 | GitHub 提交即部署 |

**核心原则**：
- 单一职责：模块、组件、表各司其职
- 契约先行：前后端共享 TS 类型（`packages/shared`）
- 约定优于配置：模块按固定目录结构自注册
- 渐进增强：核心功能离线可用，增强能力按需加载

## 4. 前端架构

### 4.1 分层

```
┌─────────────────────────────────────────┐
│  Pages / Layout（页面壳、导航）          │
├─────────────────────────────────────────┤
│  Modules（业务模块，可组合）              │
│  bill / todo / shopping / calendar / ws │
├─────────────────────────────────────────┤
│  Core（核心能力）                         │
│  auth / api / notify / offline / ui     │
├─────────────────────────────────────────┤
│  Registry（模块注册中心）★扩展关键        │
├─────────────────────────────────────────┤
│  Infrastructure（底层）                   │
│  React / Router / Query / Zustand       │
└─────────────────────────────────────────┘
```

### 4.2 模块注册中心（核心扩展机制）

每个业务模块导出一个标准 `ModuleManifest`，在应用启动时统一注册，自动挂载路由、导航、工作台卡片。

```ts
// packages/shared/types/module.ts
export interface ModuleManifest {
  key: string;                         // 'bill' | 'todo' | ...
  name: string;                        // 显示名
  icon: ReactNode | string;            // 图标
  order: number;                       // 导航排序
  roles?: Role[];                      // 可见角色
  routes: RouteConfig[];               // 路由配置
  workspaceCard?: React.FC;            // 工作台卡片（可选）
  navItem?: { label: string; to: string };
  migrations?: string;                 // 关联 DB 迁移名（仅文档）
}
```

```ts
// src/registry/index.ts
import { billModule } from '@/modules/bill';
import { todoModule } from '@/modules/todo';
// 新增模块只需在这里 import + push
export const registry = createRegistry([
  billModule, todoModule, shoppingModule, calendarModule,
]);
```

> **新增模块的完整步骤**：① 在 `modules/xxx/` 实现模块；② 导出 `ModuleManifest`；③ 在 `registry/index.ts` 注册。导航、路由、工作台卡片全自动出现。

### 4.3 模块内部结构（约定）

```
src/modules/bill/
├── index.ts            # 导出 ModuleManifest（模块入口）
├── routes.tsx          # 本模块路由
├── pages/              # 页面组件
├── components/         # 模块私有组件
├── api.ts              # 调用后端接口（基于 core/api）
├── store.ts            # Zustand 状态（如需要）
├── types.ts            # 模块类型
└── WorkspaceCard.tsx   # 工作台卡片
```

### 4.4 状态与数据策略
- **服务端状态**：统一用 React Query（缓存、失效、乐观更新、离线重试）
- **客户端状态**：Zustand（UI 状态、当前成员、会话）
- **离线写入**：进入离线队列（IndexedDB），联网后顺序重放，冲突提示

### 4.5 响应式策略
- 断点 768px：以下为移动布局（底部 Tab），以上为桌面布局（侧边导航）
- 同一套业务组件，仅在 Layout 层切换容器
- 移动端优先：所有页面先按移动设计，再补 PC 适配

## 5. 后端架构（Workers + Hono）

### 5.1 分层

```
┌─────────────────────────────────────────┐
│  Routes（路由层，Hono）                   │
├─────────────────────────────────────────┤
│  Middleware（认证/日志/错误/限流）         │
├─────────────────────────────────────────┤
│  Modules（业务服务层）                    │
│  BillService / TodoService / ...        │
├─────────────────────────────────────────┤
│  Data Access（D1 / R2 / KV）             │
├─────────────────────────────────────────┤
│  Infra（绑定、环境变量、密钥）             │
└─────────────────────────────────────────┘
```

### 5.2 路由组织（按模块）

```ts
// workers/api/src/index.ts
import { Hono } from 'hono';
import { authMiddleware } from './middleware/auth';
import { authRoutes } from './routes/auth';
import { billRoutes } from './routes/bill';
// ...

const app = new Hono<{ Bindings: Env }>();
app.route('/auth', authRoutes);          // 登录、邀请、设备
app.use('/api/*', authMiddleware);       // 以下需认证
app.route('/api/bill', billRoutes);
app.route('/api/todo', todoRoutes);
app.route('/api/shop', shopRoutes);
app.route('/api/event', eventRoutes);
app.route('/api/notify', notifyRoutes);
app.route('/api/admin', adminRoutes);    // 设备/飞书/成员管理
export default app;
```

每个模块路由独立文件，挂载到主 app。新增后端模块同样只改 `index.ts` 一处。

### 5.3 模块服务层约定

```ts
// workers/api/src/modules/bill/BillService.ts
export class BillService {
  constructor(private db: D1Database, private ctx: { familyId: string; memberId: string }) {}
  async list(query: BillQuery): Promise<BillRecord[]> { ... }
  async create(input: BillInput): Promise<BillRecord> { ... }
  async import(file: File): Promise<ImportResult> { ... }
  async stats(range: DateRange): Promise<BillStats> { ... }
}
```

所有服务统一注入 `db` 与上下文（家庭、成员），天然实现数据隔离。

### 5.4 中间件
- `authMiddleware`：校验会话 token（KV），注入 familyId / memberId
- `errorMiddleware`：统一错误响应 `{ code, message }`
- `logMiddleware`：请求日志（可投递到 Logpush）
- `rateLimitMiddleware`：PIN 错误限流（基于 KV 计数）

## 6. 设备认证 + PIN 架构（重点）

### 6.1 流程时序

```
首次绑定：
浏览器                Workers                 D1/KV
  │  输入邀请码+设PIN     │                        │
  ├────────────────────▶│ 校验邀请码               │
  │                     ├───────────────────────▶│
  │                     │ 采集设备指纹            │
  │                     │ 存 member(pin_hash)    │
  │                     │ 存 device(fingerprint, trusted=true) │
  │                     │ 存 session(token)      │
  │  返回 token          │◀───────────────────────│
  │◀────────────────────│                        │

日常登录：
浏览器                Workers                 KV
  │  输入 PIN+设备指纹   │                        │
  ├────────────────────▶│ device 查询 + PIN 校验   │
  │                     │ (bcrypt compare)       │
  │                     │ 命中且 trusted → 签 token│
  │                     ├───────────────────────▶│ 存 session
  │  返回 token          │◀───────────────────────│
  │◀────────────────────│                        │
```

### 6.2 设备指纹生成（前端）

```ts
// 采集稳定特征，避免过度隐私
async function buildFingerprint(): Promise<string> {
  const raw = [
    navigator.userAgent,
    navigator.language,
    screen.width + 'x' + screen.height,
    Intl.DateTimeFormat().resolvedOptions().timeZone,
    // 持久化的随机 id（localStorage），换浏览器会变
    getOrCreateDeviceId(),
  ].join('|');
  return await sha256(raw);   // SHA-256 哈希
}
```

> 不采集过于敏感的硬件信息；指纹用于"同一设备绑定"判定，存哈希值。

### 6.3 安全措施
- PIN：bcrypt（cost=10）哈希存储
- 设备指纹：SHA-256 存储
- 邀请码：一次性为主，可设次数 + 有效期
- 会话：token 存 KV，TTL 30 天，登出删除
- PIN 错误限流：`pin_fail:<memberId>` KV key，5 次/10min 锁定
- 吊销设备：`device.trusted=false`，下次拒绝

## 7. 通知系统架构（飞书 + Web Push）

### 7.1 双通道设计

```
                通知事件
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
   通知调度器（NotifyDispatcher）
        │                     │
   查询成员偏好           查询家庭飞书配置
        │                     │
   ┌────┴────┐                │
   ▼         ▼                ▼
Web Push  应用内通知       飞书群机器人
(FCM/VAPID) (sys_notification) (webhook)
```

### 7.2 飞书群机器人集成

**V1 方案（自定义机器人 webhook）**：
- 管理员在飞书群「设置 → 群机器人 → 添加自定义机器人」获得 webhook URL + secret
- 在「设置 → 飞书通知」填入 webhook URL + secret（加密存 D1 `sys_feishu_config`）
- 通知调度器调用 webhook 发送文本 / 富文本消息

```ts
// workers/api/src/notify/FeishuBot.ts
export async function sendFeishu(cfg: FeishuConfig, msg: FeishuMessage) {
  const timestamp = Math.floor(Date.now()0)/1000);
  const sign = signWithSecret(cfg.secret, timestamp);  // HMAC-SHA256
  await fetch(cfg.webhookUrl, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ timestamp, sign, ...msg }),
  });
}
```

**V2 升级路径**：申请飞书应用（app_id/secret），用 `im/v1/messages` 发交互卡片，支持"标记完成"按钮回调到 Workers。

### 7.3 通知类型与触发

| 通知类型 | 触发 | 默认通道 |
|----------|------|----------|
| 账单超支 | 月度某分类超过预算 | 飞书 + Web Push |
| 周期账单到期 | Cron 扫描 `bill_recurring.next_date` | 飞书 + Web Push |
| 待办到期 | Cron 扫描 `todo_item.due_at` | 飞书 + Web Push |
| 日程提醒 | Cron 扫描 `event_reminder` | 飞书 + Web Push |
| 清单更新 | 实时（有人勾选 / 新增商品） | Web Push（轻量） |
| 设备登录 | 安全提醒 | 飞书 |

### 7.4 定时调度（Workers Cron Triggers）

```toml
# wrangler.toml
[triggers]
crons = [
  "0 9 * * *",      # 每天 9 点：日程/生日提醒
  "*/30 * * * *",   # 每 30 分钟：待办到期
  "0 0 * * *",      # 每天 0 点：周期账单生成 + 当日预算检查
]
```

Cron handler 内调用各模块的 `checkAndNotify()`，命中规则则入通知队列（Workers Queues）异步发送，避免超时。

### 7.5 通知偏好
- 每成员对每类通知可设：飞书开/关、Web Push 开/关
- 默认：重要通知（日程/到期）双发，轻量通知（清单）仅 Web Push

## 8. 数据架构

### 8.1 D1 schema 管理
- 迁移文件：`workers/api/migrations/0001_init.sql`、`0002_bill_tag.sql` ...
- 部署时自动应用：`wrangler d1 migrations apply family-hub`
- 每个迁移文件对应 PRD 一个模块上线

### 8.2 缓存策略（KV）
| 用途 | key | TTL |
|------|-----|-----|
| 会话 | `sess:<token>` | 30 天 |
| 邀请码 | `invite:<code>` | 有效期 |
| PIN 限流 | `pinfail:<memberId>` | 10min |
| 家庭飞书配置缓存 | `feishu:<familyId>` | 1h |
| 分类树缓存 | `cat:<familyId>` | 1h |

### 8.3 R2 存储
- `bills/<familyId>/<recordId>.jpg` 小票
- `avatars/<memberId>.png` 头像
- `imports/<familyId>/<jobId>.xlsx` 导入文件 / 错误报告
- 通过 Workers 生成临时签名 URL 上传 / 下载

### 8.4 备份
- D1：Cloudflare 每日自动备份 + 手动导出到 R2
- R2：跨区域冗余

## 9. CI/CD 架构（GitHub → Cloudflare）

### 9.1 流程

```
开发者 push feature 分支
        │
        ▼
   开 PR 到 dev
        │  CI：lint + typecheck + test + build
        ▼
   合并到 dev → 触发 Preview Deployment（独立预览 URL）
        │
        ▼
   开 PR dev → main，审核通过合并
        │
        ▼
   main 分支自动部署生产：
   ├─ Pages build & deploy（前端）
   ├─ wrangler deploy（Workers）
   └─ wrangler d1 migrations apply（D1）
```

### 9.2 GitHub Actions 示例

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main, dev]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint && pnpm typecheck && pnpm test
      - run: pnpm --filter web build
      - name: Deploy Workers
        run: pnpm --filter api exec wrangler deploy
        env: { CLOUDFLARE_API_TOKEN: ${{secrets.CF_API_TOKEN}} }
      - name: Apply D1 migrations
        run: pnpm --filter api exec wrangler d1 migrations apply family-hub --remote
        env: { CLOUDFLARE_API_TOKEN: ${{secrets.CF_API_TOKEN}} }
```

> Pages 前端可直接在 Cloudflare Dashboard 绑定 GitHub 仓库，推 main 自动构建（无需 Actions），Workers 走 Actions。两种方式按习惯选择。

### 9.3 环境与密钥
| 项 | 管理 |
|----|------|
| D1 / R2 / KV 绑定 | `wrangler.toml` |
| 飞书 webhook / secret | `wrangler secret put FEISHU_*` 或 DB |
| VAPID 密钥 | `wrangler secret put VAPID_*` |
| GitHub Secret | `CF_API_TOKEN` |

### 9.4 回滚
- Cloudflare Pages / Workers 均支持一键回滚到历史版本
- D1 迁移需准备 down 迁移脚本

## 10. 安全设计

| 层 | 措施 |
|----|------|
| 传输 | 全程 HTTPS（Cloudflare 自动） |
| 认证 | 设备 + PIN 双因子，PIN bcrypt，设备指纹 SHA-256 |
| 会话 | token 随机 + KV 存储 + TTL + 登出失效 |
| 授权 | 每请求校验 familyId / memberId + 角色检查 |
| 输入 | zod 校验所有入参（前后端共享） |
| 限流 | PIN 错误限流；通用 API 限流（Cloudflare WAF） |
| 密钥 | 所有密钥用 wrangler secret，不入仓库 |
| 飞书 | webhook + secret 加密存储；签名校验 |
| 文件 | 上传走签名 URL，大小 / 类型校验 |
| 日志 | 不记录 PIN、token、敏感字段 |

## 12. 可扩展性

- **新业务模块**：前端导出 Manifest + 注册；后端新增 route + service

## 13. 关键技术风险与对策

| 风险 | 对策 |
|------|------|
| D1 单库写入瓶颈 | 单家庭量级无忧；预留分表/分库方案 |
| iOS Web Push 限制 | 飞书通道兜底；引导添加到主屏 |
| 离线冲突 | 最后写入为主 + 冲突提示；V2 字段级合并 |
| 飞书机器人限流 | 合并通知（按家庭 5 分钟聚合） |
| 设备指纹不稳定 | localStorage deviceId 兜底 + 管理员重信任 |
